# Portfolio Library 技术操作路线（数据库重点）

## 1. 项目定位

Portfolio Library 是一个本地优先的个人资产库与作品主页发布工具。用户在本地上传或登记图片、视频、音频、文档等资产，将资产组织成 Work，设置公开状态和授权状态，再把公开作品导出为可静态托管的个人主页快照。

当前技术栈：

- 前端：React + Vite
- 后端：Flask + PyMySQL
- 数据库：MySQL
- 桌面打包：Electron + PyInstaller + electron-builder
- 静态主页模板：内置 `creator_gallery`

核心数据流：

```text
MySQL 数据库
  -> Flask API 查询并校验
  -> Creator Workspace Schema
  -> creator_gallery adapter
  -> exports/snapshot-xx 静态站点目录
  -> zip 下载 / Git deploy
```

## 2. 数据库总体设计

数据库采用 MySQL，主库名建议使用：

```text
portfolio_library
```

开发配置在 `backend/config.py` 中读取环境变量：

```text
DB_HOST
DB_PORT
DB_USER
DB_PASSWORD
DB_NAME
```

桌面版 Electron 启动时会为 Flask 注入这些环境变量，使后端连接 Electron 管理的内置 MySQL。

初始化脚本：

```text
db/creator_workspace_minimal.sql
```

该脚本会创建项目当前核心表、视图和 demo 用户。

## 3. 核心表结构

### 3.1 user_account

用途：保存登录账号。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `user_id` | 用户主键 |
| `username` | 用户名，唯一 |
| `email` | 邮箱，唯一 |
| `password_hash` | 密码哈希 |
| `account_status` | `active` / `disabled` |
| `last_login_at` | 最近登录时间 |

关联：

- `creator_profile.user_id`
- `work.owner_id`
- `media_asset.owner_id`
- `tag.owner_id`
- `publish_snapshot.user_id`

删除用户时，相关 profile、work、asset、tag、snapshot 会通过外键级联删除。

### 3.2 creator_profile

用途：保存公开主页的创作者信息和主页配置。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `profile_id` | 资料主键 |
| `user_id` | 所属用户 |
| `display_name` | 主页展示名称 |
| `bio` | 个人简介 |
| `avatar_url` | 外部头像链接 |
| `homepage_config` | JSON 主页配置 |

`homepage_config` 当前保存：

```json
{
  "template_id": "creator_gallery",
  "theme": "warm_gallery",
  "accent_color": "#8fb8a8",
  "featured_work_ids": [],
  "creator_tags": ["Portfolio", "Archive"],
  "contact_links": [
    { "label": "Email", "url": "mailto:hello@example.com" }
  ],
  "license_text": "Unless otherwise noted..."
}
```

说明：

- 使用 JSON 字段是为了让首页配置扩展更灵活。
- 后续增加模板配置、主题、联系方式、头像 asset id 时，不必频繁改表。

### 3.3 media_asset

用途：保存资产文件元数据。资产文件本体存放在文件系统，数据库只保存路径和状态。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `asset_id` | 资产主键 |
| `owner_id` | 所属用户 |
| `asset_name` | 原始文件名或用户命名 |
| `media_type` | `image` / `video` / `audio` / `document` / `other` |
| `local_path` | 本地实际文件路径 |
| `thumbnail_path` | 缩略图路径 |
| `public_export_path` | 可公开导出的替代路径 |
| `file_size` | 文件大小 |
| `mime_type` | MIME 类型 |
| `visibility` | `private` / `public` |
| `import_status` | `active` / `missing` / `archived` |
| `file_exists` | 最近检查时文件是否存在 |

设计要点：

- `media_type` 表示文件类型，不表示作品展示方式。
- 资产可以归档，归档不同于删除。
- 删除 asset 会删除它和 Work 的绑定关系，但不会影响其他资产。
- 发布时不会导出 private、archived、restricted 资产。

### 3.4 asset_license_note

用途：保存资产授权状态。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `asset_id` | 对应资产 |
| `authorization_status` | `original` / `licensed` / `unknown` / `restricted` |
| `source_name` | 来源名称 |
| `source_url` | 来源链接 |
| `license_note` | 授权备注 |
| `allow_public_display` | 是否允许公开展示 |
| `attribution_required` | 是否需要署名 |

发布规则：

- `restricted` 不导出。
- `unknown` 可以导出，但进入 publish warning。
- `original` 和 `licensed` 默认适合公开展示。

### 3.5 work

用途：保存作品。公开主页以 Work 为中心展示，不直接以 Asset 列表展示。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `work_id` | 作品主键 |
| `owner_id` | 所属用户 |
| `title` | 标题 |
| `description` | 必填，作品基本说明 |
| `summary` | 卡片短摘要 |
| `body` | 详情长文 |
| `content_type` | Work 级展示类型 |
| `cover_mode` | 封面展示方式 |
| `cover_asset_id` | 指定封面资产 |
| `work_type` | 旧分类字段 |
| `visibility` | `private` / `public` |
| `work_status` | `draft` / `ready` / `archived` |

Work 展示字段说明：

```text
asset.media_type    文件类型
work.content_type   作品整体展示类型
work.cover_mode     卡片封面策略
```

`content_type` 可选：

```text
auto | visual | text | mixed | document | video | audio | collection
```

`cover_mode` 可选：

```text
auto | image | title
```

当前业务约束：

- 新建 Work 默认 `visibility = public`。
- 新建 Work 默认 `work_status = ready`。
- `description` 已在前后端同步设置为必填。
- 文档 asset 可以提取文本填充到 `body`，不会覆盖 `description`。

### 3.6 work_media

用途：Work 与 Asset 的多对多绑定表。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `work_id` | 作品 |
| `asset_id` | 资产 |
| `role` | `cover` / `main` / `process` / `reference` / `attachment` |
| `display_order` | 展示顺序 |
| `is_public` | 该资产在这个 Work 中是否公开 |

设计意义：

- 一个 Work 可以绑定多个 Asset。
- 一个 Asset 可以复用到多个 Work。
- Asset 自身 public 不代表一定在某个 Work 中公开，还要看 `work_media.is_public`。

### 3.7 tag 与 work_tag

用途：标签与作品标签关系。

`tag` 保存标签定义：

```text
style | topic | series | character | tool | custom
```

`work_tag` 保存 Work 与 Tag 的多对多关系。

发布时会根据公开 Work 的标签生成：

```text
data/tags.json
```

### 3.8 publish_snapshot

用途：保存每次发布快照记录。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `snapshot_id` | 快照主键 |
| `user_id` | 所属用户 |
| `snapshot_name` | 快照名称 |
| `output_dir` | 静态站点导出目录 |
| `homepage_config` | 发布时主页配置 |
| `public_data` | 发布时统一 schema |
| `status` | `draft` / `generated` / `failed` |
| `package_size_bytes` | 导出包大小 |
| `created_at` | 创建时间 |

说明：

- snapshot 是历史记录。
- 旧 snapshot 可以打开、下载、重命名、删除。
- Git Deploy Assistant 使用 snapshot 的 `output_dir` 作为发布源。

### 3.9 publish_report

用途：保存发布检查结果。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `snapshot_id` | 对应快照 |
| `check_type` | 检查类型 |
| `severity` | `info` / `warning` / `error` |
| `message` | 检查信息 |
| `related_table` | 关联表 |
| `related_id` | 关联记录 |

发布检查包含：

- restricted asset 不导出
- private asset 不导出
- unknown authorization 进入 warning
- 大文件 warning
- 本地路径泄露检查
- 敏感文件检查
- API key pattern 检查

## 4. 数据库视图

### 4.1 v_workspace_asset

合并 `media_asset` 与 `asset_license_note`。

前端资产列表主要使用这个视图，避免每次手写 license join。

### 4.2 v_workspace_work

合并 Work 基础信息和资产数量统计。

包括：

- `asset_count`
- `public_asset_count`

### 4.3 v_publishable_work

筛选可以发布的 Work：

```sql
WHERE visibility = 'public'
  AND work_status = 'ready'
```

### 4.4 v_publish_report_summary

统计每个 snapshot 的 warning/error/info 数量，供 Publish 页面展示。

## 5. 主要业务流程

### 5.1 用户注册与登录

相关代码：

```text
backend/routes/user.py
backend/auth.py
backend/db.py
```

流程：

1. 用户注册写入 `user_account`。
2. 同时创建 `creator_profile`。
3. 登录校验密码哈希。
4. 后端返回 token。
5. 后续 API 通过 token 识别 `g.user_id`。

### 5.2 上传资产

相关代码：

```text
backend/routes/assets.py
frontend/src/pages/AssetsPage.jsx
frontend/src/components/AssetInspector.jsx
```

流程：

1. 前端上传文件到 `/api/assets/upload`。
2. 后端把文件复制到 `UPLOAD_ROOT/user-<id>/`。
3. 写入 `media_asset`。
4. 写入或更新 `asset_license_note`。
5. 前端展示预览。

格式识别逻辑：

- 先看原始文件名扩展名。
- 再看 MIME。
- Markdown、DOCX、PPTX、PDF 都会按 document 处理。

### 5.3 资产归档、删除、替换

当前已有：

- archive：更新 `media_asset.import_status = archived`
- restore：恢复 `active`
- delete：删除 `media_asset`，同时删除 `work_media` 与 `asset_license_note`

建议后续新增：

```text
POST /api/assets/<asset_id>/replace-file
```

目的：

- 保留 `asset_id`
- 保留 Work 绑定关系
- 只替换底层文件路径、大小、MIME、media_type

这能避免“删除 -> 重新上传 -> 重新绑定 Work -> 重新发布”的复杂流程。

### 5.4 创建和编辑 Work

相关代码：

```text
backend/routes/workspace.py
frontend/src/pages/WorksPage.jsx
frontend/src/pages/WorkEditorPage.jsx
```

流程：

1. 创建 Work 写入 `work`。
2. 绑定 Asset 写入 `work_media`。
3. 设置 `cover_asset_id`、`content_type`、`cover_mode`。
4. 设置公开状态与 ready 状态。
5. 发布时只导出 public + ready 的 Work。

封面选择规则：

1. 如果 `cover_asset_id` 指向 public image asset，使用它作为封面。
2. 否则选择 Work 下第一个 public image asset。
3. 如果没有图片但有视频，尝试用 ffmpeg 抽取第一帧。
4. 如果仍没有封面，静态主页使用 title-card。

### 5.5 文档文本提取

相关代码：

```text
backend/document_extract.py
backend/routes/workspace.py
backend/routes/assets.py
```

支持：

- `.txt`
- `.md`
- `.markdown`
- `.docx`
- `.pptx`
- `.pdf`

用途：

- Assets 页预览文档内容。
- Work 编辑页可以把文档文本填入 `body`。
- 发布时文档 asset 的公开文本可以进入 `works.json`，用于静态主页详情预览。

## 6. 发布导出路线

相关代码：

```text
backend/creator_publish.py
backend/routes/publish.py
backend/templates/creator_gallery/
frontend/src/pages/PublishCenterPage.jsx
```

发布链路：

```text
work / media_asset / tag / creator_profile
  -> build_portfolio_library_schema()
  -> Creator Workspace Schema
  -> CreatorGalleryAdapter.render()
  -> exports/snapshot-xx/
  -> publish_snapshot / publish_report
```

导出目录结构：

```text
snapshot-xx/
  index.html
  styles.css
  main.js
  README.md
  publish_report.json
  data/
    profile.json
    works.json
    homepage.json
    tags.json
  media/
    avatar.*
    works/
      work_1_01.png
      work_1_02.pdf
```

### 6.1 Creator Workspace Schema

发布时统一生成中间 JSON，不让模板直接读数据库。

核心结构：

```json
{
  "profile": {},
  "works": [],
  "homepage": {},
  "tags": []
}
```

Work 导出字段：

```json
{
  "id": "work_1",
  "title": "作品标题",
  "summary": "卡片摘要",
  "body": "详情正文",
  "description": "基本说明",
  "content_type": "visual",
  "cover_mode": "auto",
  "cover": "media/works/work_1_01.png",
  "tags": ["tag"],
  "featured": true,
  "authorization_status": "licensed",
  "visibility": "public",
  "assets": []
}
```

### 6.2 安全检查

发布报告写入：

```text
publish_report.json
publish_report 表
```

检查目标：

- 防止本地路径泄露到公开 HTML/JSON
- 防止 `.env`、`.sqlite`、数据库 dump 被打包
- 标记大文件
- 标记 unknown license
- 跳过 restricted / private asset

### 6.3 静态模板渲染

内置模板：

```text
backend/templates/creator_gallery/
  index.html
  styles.css
  main.js
```

模板特性：

- 以 Work 为中心展示。
- 支持 image-card 与 title-card。
- 支持 Work 详情 modal。
- 支持 PDF、Markdown、DOCX 文本预览。
- 支持图片、视频、音频展示。
- 页面不显示 local_path、asset_id、Warnings、Errors 等调试信息。

## 7. Snapshot 管理与下载

数据库表：

```text
publish_snapshot
publish_report
```

前端能力：

- Generate snapshot
- Open snapshot
- Download zip
- Rename
- Delete
- Git Deploy

下载 zip 时后端会：

1. 检查 snapshot 属于当前用户。
2. 检查 `output_dir` 位于 `EXPORT_ROOT` 内。
3. 写入或刷新 README。
4. 压缩完整静态站点目录。
5. 返回 zip。

## 8. Git Deploy Assistant 路线

相关代码：

```text
backend/routes/publish.py
frontend/src/pages/PublishCenterPage.jsx
```

接口：

```text
POST /api/publish/snapshots/<snapshot_id>/git-deploy
```

请求：

```json
{
  "repo_url": "https://github.com/YOUR_NAME/YOUR_REPO.git",
  "branch": "main",
  "commit_message": "Update portfolio snapshot"
}
```

流程：

1. 检查 Git 是否存在。
2. 找到 snapshot 的 `output_dir`。
3. 在 `EXPORT_ROOT/git-deploy/<repo-name>/` 创建或复用本地 Git 仓库。
4. 复制 snapshot 静态文件到该仓库。
5. `git add .`
6. 若有变化，执行 `git commit`。
7. `git push -u origin main`。

为什么要复制 snapshot：

- snapshot 是发布历史记录，不应直接塞 `.git`。
- Git 仓库代表“当前部署版本”。
- 多个 snapshot 可以保留，Git deploy 目录只维护目标仓库的当前内容。

## 9. Electron 桌面版数据库路线

桌面版目标：

```text
用户双击桌面应用
  -> Electron 启动
  -> 启动内置 MySQL
  -> 初始化 schema
  -> 启动 Flask 后端
  -> 加载 React UI
```

关键目录：

```text
desktop/runtime/mysql/
```

运行时数据目录位于 Electron `userData`：

```text
C:\Users\<User>\AppData\Roaming\portfolio-library-desktop\
  mysql-data/
  uploads/
  exports/
  logs/
```

Electron 会注入：

```text
DB_HOST=127.0.0.1
DB_PORT=<dynamic>
DB_USER=root
DB_PASSWORD=
DB_NAME=portfolio_library
UPLOAD_ROOT=<userData>/uploads
EXPORT_ROOT=<userData>/exports
```

这样桌面版不会污染源码目录，也不会依赖用户手动启动 MySQL。

## 11. 推荐演示路线

### 11.1 数据库准备

1. 初始化 MySQL schema。
2. 注册或使用 demo 用户。
3. 确认 `creator_profile` 已有 homepage_config。

1. 上传图片、视频、音频、Markdown、DOCX、PDF。

1. Run check。
2. Generate snapshot。
3. 打开静态主页。
4. 查看 `publish_snapshot` 与 `publish_report`。

6. Git Deploy。

## 12. 当前限制与后续扩展

当前限制：

- Git Deploy 依赖本机 Git 和 GitHub 凭据。
- 不自动管理 GitHub token。
- PDF 预览依赖浏览器内置 PDF viewer。
- 视频封面抽帧依赖 ffmpeg。
- 资产替换功能还建议新增，减少删除重传成本。

后续可扩展：

- `POST /api/assets/<asset_id>/replace-file`
- 多模板 registry
- 每个 Work 单独详情页
- 更完整的 schema migration 管理
- 数据库备份与恢复
- GitHub Pages token 化自动部署
- 静态站点增量发布

## 13. 打包前数据库相关检查清单

打包前建议确认：

- `db/creator_workspace_minimal.sql` 是最新 schema。
- `desktop/runtime/mysql/bin/mysqld.exe` 存在。
- PyInstaller 后端 exe 已重新构建。
- Electron 启动时 `DB_NAME=portfolio_library`。
- `UPLOAD_ROOT` 和 `EXPORT_ROOT` 指向 Electron `userData`。
- demo 初始化不强塞大量资产，便于课堂现场演示上传流程。
- 发布 zip 中不包含本地绝对路径。

常用检查：

```sql
SHOW TABLES;
SELECT COUNT(*) FROM user_account;
SELECT COUNT(*) FROM media_asset;
SELECT COUNT(*) FROM work;
SELECT COUNT(*) FROM publish_snapshot;
```

发布检查：

```sql
SELECT * FROM v_publish_report_summary ORDER BY created_at DESC;
```
